# Sunny

A mobile-first voice conversation experience. The central sparkle responds to microphone input and Sunny's speech.

The voice conversation loop in [`VoiceAgent.svelte`](./src/components/VoiceAgent.svelte) records speech in the browser, sends audio to Deepgram for transcription, streams responses from Venice, and plays speech generated by OpenAI. These provider calls are made through Netlify Functions; the browser needs microphone and MediaRecorder support. [`Microphone.svelte`](./src/components/Microphone.svelte) and [`Speaker.svelte`](./src/components/Speaker.svelte) manage audio input and output, [`Sparkle.svelte`](./src/components/Sparkle.svelte) handles audio visualization, and [`Footer.svelte`](./src/components/Footer.svelte) displays progress and status.

Speech audio is prefetched two sentences ahead and played in order. The current OpenAI TTS model is deprecated and scheduled for shutdown on January 6, 2027; OpenAI's replacement requires a Realtime API migration.

The current session's `intro` is the spoken opening, and its `prompt` supplies the conversation system prompt sent with Venice requests. The current session is the first outline entry until session progression is connected.

[`outline.ts`](./src/lib/sessions/outline.ts) collects the individual baby-step definitions in order, organized as `step/phase/name.ts` using lowercase, hyphenated names. Each definition has its own starter prompt and a shared condition accepting `sessionStart` and `previousSessionEnd` as `Date` values (or `null` for the first session). The condition requires at least 18 hours between the previous session's end and the new session's start. The conditions are not yet connected to session scheduling.

The **Sessions** menu shows the outline and lets users open an enabled session. Previously started sessions can be continued or restarted; restarting marks existing messages deleted rather than erasing them. Each session's chat is stored separately in this browser. Completion tracking is not implemented, so conditions currently receive no prior session end and all existing session conditions allow access.

Session selection, availability, local storage, and chat initialization are managed in [`session-manager/`](./src/lib/session-manager/); the outline and session content remain in [`sessions/`](./src/lib/sessions/).

New chat messages retain their creation timestamp in saved history without displaying it in the chat. Older saved messages do not have recoverable timestamps.

Use **Show logger** in the menu to view the most recent 200 application log entries on the device; **Show chat** returns to the conversation. Logs are kept in memory only and may include conversation text and error details.

Use **Report** in the menu to request a JSON session report from Venice and display it in the logger without speech. Reports are saved in browser local storage and can contain sensitive conversation details. The `firstTimestamp` and `lastTimestamp` fields are the stored UTC timestamps of the first and last messages in that history; they are `null` when unavailable. Its generated fields and rating are validated before saving and logging; errors appear in the logger. Reports previously printed only to the logger cannot be recovered.

Reports include `totalTimeSeconds` (elapsed time between the first and last visible messages of the current baby-step chat, including pauses and time away), `totalTokens` (input plus output), and `totalEstimatedCostUsd`. Time is `null` when either timestamp is unavailable or out of order. Restarting clears the visible chat and starts a new elapsed-time span; usage and cost totals continue to include all recorded requests for the baby step, including prior restarts. Token and cost totals may be estimated or incomplete, as indicated by the usage details below.

When starting or restarting a session, Sunny sends the account first name and local settings (when available), the current session details, and the selected prior report to Venice to generate a personalized spoken and displayed intro. The prior report is the latest saved report for the preceding outline session, or, if absent, the report from the most recently active different session (based on its last chat timestamp, or report time if unavailable). Continuing an existing chat does not generate a new intro. This context is also supplied to conversation and report requests; account IDs, report usage and other chat histories are not included. Report generation uses the account first name when no preferred name can be extracted from the conversation. Intro generation is included in session usage.

When reopening an incomplete session at least one hour after its last non-empty transcription, Sunny speaks a brief welcome-back message without adding it to the conversation. A saved report with a satisfaction rating for the current chat marks it complete for this greeting; a restarted chat is treated separately. Speech usage is still included in the session's usage records.

Usage records are saved alongside the session chat in browser storage, including requests
for replays and reports and requests associated with deleted or restarted chats. On localhost,
each chat bubble displays its associated usage and estimated cost; the session report contains
totals for the entire saved session. Older messages have no recoverable usage records. Pending,
failed, interrupted, or provider responses without usage remain marked as unknown, so totals
can be incomplete; `unknownCosts` and `unknownTokenRequests` indicate this.

Venice reports input and output tokens. Deepgram reports audio duration, not token counts.
OpenAI's speech endpoint returns audio without token usage, so TTS tokens and duration are
rough estimates: four characters per input token (including voice instructions), 150 words
per minute adjusted for the configured 1.3x speed, and 25 audio tokens per second. Prices are
estimates in USD using public pay-as-you-go rates: [Venice GLM 5.2](https://docs.venice.ai/models/glm-5-2.md)
($1.40 input / $4.40 output per million tokens), [OpenAI GPT-4o mini TTS](https://developers.openai.com/api/docs/models/gpt-4o-mini-tts)
($0.60 text input / $12 audio output per million tokens), and [Deepgram Nova-3 prerecorded](https://deepgram.com/pricing)
($0.0043 per minute). Actual charges may differ due to provider rates, billing increments,
discounts, tokenization, and speech duration. Review these rates when changing models or plans.

Speech is sent after the microphone level falls below the speech threshold for the interval set by `speechSilenceTimeoutMs` in [`VoiceAgent.svelte`](./src/components/VoiceAgent.svelte). Recordings are limited to 60 seconds. Transcription is returned after recording, not displayed live. Audio and conversation text are sent to the configured providers, so an internet connection and working provider credentials are required.

## Local development

```bash
npm install
npm run dev
```

`npm run dev` starts Vite on port 5173 and the Netlify Functions server on port 9999. Vite proxies `/.netlify/functions/*` requests to the local functions.

Stop the development server before running `npm run build`. The Netlify adapter writes
generated functions during the build, which can cause the running Netlify Functions
server to lose its locally registered functions. If function requests return
`404 Function not found...` after a build, restart `npm run dev` and reload the page.
The functions server explicitly loads `.env` and runs in offline mode so local values are not
overridden by environment values from a linked Netlify site. Create `.env` before starting the server and restart it after changing the keys. Open
`http://localhost:5173`.

The voice loop requires microphone permission and the following server-side keys:

```bash
VENICE_API_KEY=...
DEEPGRAM_API_KEY=...
SUNNY_OPENAI_API_KEY=...
```

Run `npm run verify:venice` to make a minimal Venice chat completion request.

Configure all three keys in Netlify under **Site configuration → Environment variables**. Never expose them in `PUBLIC_` variables or client-side code.

### User accounts

The **Sign in** menu option opens `/user`. Users enter their first name and email, then sign in or create an account with an emailed one-time code through Stytch. The verified Stytch user ID and first name are stored in browser local storage for other pages to use and the first name is upserted to Supabase after the Stytch session is verified server-side. Signing out clears the current local identity.

Sunny creates a random InitialUID in local storage on first use. It identifies this browser's storage, not a physical device or a person, and remains across sign-outs but is lost if site data is cleared. On sign-in, the browser ID is associated with the verified Stytch user locally and in Supabase; more than one account can be associated with the same browser. It is not a credential and must not be used to authorize access. If the remote save fails, the account page offers a retry. The association does not upload or attach anonymous conversations. Location is not collected or stored.

Set these variables for local development and in Netlify for deployment:

```bash
VITE_STYTCH_PUBLIC_TOKEN=public-token-test-...
STYTCH_PROJECT_ID=project-test-...
STYTCH_SECRET=...
STYTCH_API_URL=https://test.stytch.com
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
```

Only `VITE_STYTCH_PUBLIC_TOKEN` is exposed in the browser bundle. Keep `STYTCH_SECRET` and `SUPABASE_SERVICE_ROLE_KEY` server-side; never use a `VITE_` prefix for either secret. For a live Stytch project, set `STYTCH_API_URL=https://api.stytch.com`. Enable email OTP in Stytch and apply the migrations in [`supabase/migrations/`](./supabase/migrations/) to Supabase before saving profiles. The `sunny_profiles` and `sunny_browser_associations` tables deny direct access to browser roles; only the Netlify function can write to them.

Conversation history and reports are saved in browser storage and synchronized to Supabase under the anonymous browser identity, including existing history on first sync. A separate random credential in browser storage authorizes writes; InitialUID alone is not a credential. The browser retries when synchronization fails or connectivity returns, and reports the failure in the chat. The application must remain open for retries. Clearing browser storage loses the identifier and credential; remote recovery is not currently available. A browser without Web Locks cannot safely synchronize and will report an error.

The browser-to-account association does not grant account access to this anonymous history; consent-based account attachment and cross-device restoration are not yet implemented. Signing out does not clear local or remote history. **Delete chat history** marks messages as deleted and hides them from the chat and future prompts, but does not erase them from browser storage or Supabase. Avoid using a shared device if retaining conversation history there is a concern.

The app is mobile-first and becomes a framed phone layout on larger screens.

## Build

```bash
npm run check
npm run build
```

To run the report validation tests with Node.js 22.6 or newer:

```bash
node --experimental-strip-types --test tests/session-report.test.mjs
```

Run the baby-step definition and timing tests with `node --test tests/baby-steps.test.mjs`.

## Publish to GitHub

Create an empty repository on GitHub, then run:

```bash
git init
git add .
git commit -m "Create Sunny audio-reactive experience"
git branch -M main
git remote add origin https://github.com/<your-account>/<your-repository>.git
git push -u origin main
```

## Publish to Netlify

Import the GitHub repository into Netlify. The included [`netlify.toml`](./netlify.toml) configures:

- Build command: `npm run build`
- Publish directory: `.svelte-kit/netlify`

Configure `VENICE_API_KEY`, `DEEPGRAM_API_KEY`, and `SUNNY_OPENAI_API_KEY` in Netlify.
