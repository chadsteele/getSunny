# Sunny

A mobile-first voice conversation experience. The central sparkle responds to microphone input and Sunny's speech.

The voice conversation loop in [`VoiceAgent.svelte`](./src/components/VoiceAgent.svelte) records speech in the browser, sends audio to Deepgram for transcription, streams responses from Venice, and plays speech generated by OpenAI. These provider calls are made through Netlify Functions; the browser needs microphone and MediaRecorder support. [`Sparkle.svelte`](./src/components/Sparkle.svelte) renders the audio-reactive visual, while [`Footer.svelte`](./src/components/Footer.svelte) provides microphone and speaker controls.

Speech audio is prefetched two sentences ahead and played in order. The current OpenAI TTS model is deprecated and scheduled for shutdown on January 6, 2027; OpenAI's replacement requires a Realtime API migration.

The first entry in [`prompts.ts`](./src/lib/prompts.ts) is the spoken opening; the second is the conversation system prompt sent with Venice requests.

New chat messages retain their creation timestamp in saved history without displaying it in the chat. Older saved messages do not have recoverable timestamps.

Use **Show logger** in the menu to view the most recent 200 application log entries on the device; **Show chat** returns to the conversation. Logs are kept in memory only and may include conversation text and error details.

Use **Report** in the menu to request a JSON session report from Venice and display it in the logger without speech. The report uses the conversation history available at the time of the request, and can contain sensitive conversation details. The `firstTimestamp` and `lastTimestamp` fields are the stored UTC timestamps of the first and last messages in that history; they are `null` when unavailable. Its generated fields and rating are validated before logging; errors appear in the logger.

Speech is sent after the microphone level falls below the speech threshold for the interval set by `speechSilenceTimeoutMs` in [`VoiceAgent.svelte`](./src/components/VoiceAgent.svelte). Recordings are limited to 60 seconds. Transcription is returned after recording, not displayed live. Audio and conversation text are sent to the configured providers, so an internet connection and working provider credentials are required.

## Local development

```bash
npm install
npm run dev
```

`npm run dev` starts Vite on port 5173 and the Netlify Functions server on port 9999. Vite proxies `/.netlify/functions/*` requests to the local functions.
The functions server explicitly loads `.env` and runs in offline mode so local values are not
overridden by environment values from a linked Netlify site. Create `.env` before starting the server and restart it after changing the keys. Open
`http://localhost:5173`.

The voice loop requires microphone permission and the following server-side keys:

```bash
VENICE_API_KEY=...
DEEPGRAM_API_KEY=...
SUNNY_OPENAI_API_KEY=...
```

Run `npm run verify:venice` to make a minimal Venice chat completion request.

Configure all three keys in Netlify under **Site configuration → Environment variables**. Never expose them in `PUBLIC_` variables or client-side code.

### User accounts

The **Sign in** menu option opens `/user`. Users enter their first name and email, then sign in or create an account with an emailed one-time code through Stytch. The verified Stytch user ID and first name are stored in browser local storage for other pages to use and the first name is upserted to Supabase after the Stytch session is verified server-side. Signing out clears the current local identity.

Set these variables for local development and in Netlify for deployment:

```bash
VITE_STYTCH_PUBLIC_TOKEN=public-token-test-...
STYTCH_PROJECT_ID=project-test-...
STYTCH_SECRET=...
STYTCH_API_URL=https://test.stytch.com
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
```

Only `VITE_STYTCH_PUBLIC_TOKEN` is exposed in the browser bundle. Keep `STYTCH_SECRET` and `SUPABASE_SERVICE_ROLE_KEY` server-side; never use a `VITE_` prefix for either secret. For a live Stytch project, set `STYTCH_API_URL=https://api.stytch.com`. Enable email OTP in Stytch and apply the migration in [`supabase/migrations/`](./supabase/migrations/) to Supabase before saving profiles. The `sunny_profiles` table denies direct access to browser roles; only the Netlify function can write to it.

Conversation history remains in browser storage and is not tied to the signed-in account; signing out does not clear it. On a shared device, use **Delete chat history** before leaving.

The app is mobile-first and becomes a framed phone layout on larger screens.

## Build

```bash
npm run check
npm run build
```

To run the report validation tests with Node.js 22.6 or newer:

```bash
node --experimental-strip-types --test tests/session-report.test.mjs
```

## Publish to GitHub

Create an empty repository on GitHub, then run:

```bash
git init
git add .
git commit -m "Create Sunny audio-reactive experience"
git branch -M main
git remote add origin https://github.com/<your-account>/<your-repository>.git
git push -u origin main
```

## Publish to Netlify

Import the GitHub repository into Netlify. The included [`netlify.toml`](./netlify.toml) configures:

- Build command: `npm run build`
- Publish directory: `.svelte-kit/netlify`

Configure `VENICE_API_KEY`, `DEEPGRAM_API_KEY`, and `SUNNY_OPENAI_API_KEY` in Netlify.

## Development requirements

Use Node.js 22.13 or newer. The repository includes an [.nvmrc](./.nvmrc) file for
`nvm` users:

```bash
nvm install
nvm use
npm install
```
